1Что такое ООП и зачем оно нужно

Объектно-ориентированное программирование (ООП) — это способ писать программы, при котором данные и действия над ними объединяются в одно целое — объект. Программа становится набором объектов, которые хранят своё состояние и умеют что-то делать.

Сначала — процедурный подход

До сих пор вы писали процедурно: данные лежат в переменных и словарях, а функции живут отдельно и получают эти данные аргументами. Пример — банковский счёт:

account = {"owner": "Анна", "balance": 1000}

def deposit(acc, amount):
    acc["balance"] += amount

def withdraw(acc, amount):
    if amount > acc["balance"]:
        print("Недостаточно средств")
        return
    acc["balance"] -= amount

deposit(account, 500)
withdraw(account, 200)
print(account["balance"])  # 1300

Пока программа маленькая, это работает. Но проблемы уже видны:

  • ничто не мешает написать account["balance"] = -999999 и обойти проверку в withdraw;
  • опечатка в ключе ("balanse") найдётся только во время работы;
  • функции для счёта разбросаны по коду, и не понятно, какие из них относятся к счёту, а какие — к чему-то другому.

То же самое в стиле ООП

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            print("Недостаточно средств")
            return
        self.balance -= amount

account = BankAccount("Анна", 1000)
account.deposit(500)
account.withdraw(200)
print(account.balance)  # 1300

Теперь данные (owner, balance) и действия (deposit, withdraw) лежат в одном месте. Вызов account.deposit(500) читается как обычное предложение: «счёт, положи 500». В разделе про инкапсуляцию мы ещё и запретим прямо портить баланс.

2Класс и объект

Класс — это шаблон (чертёж), который описывает, какие данные будут у объектов и что они смогут делать. Объект (или экземпляр) — это конкретная вещь, созданная по этому шаблону. Класс один, объектов может быть сколько угодно.

ТерминПростыми словамиПример
КлассЧертёж, типCat
Объект / экземплярКонкретная вещь по чертежуmurka = Cat()
Атрибут (поле, свойство)Данные объекта, его «прилагательные»murka.name, murka.age
МетодФункция внутри класса, «глагол» объектаmurka.meow()

Синтаксис объявления класса

class Cat:
    pass

Разберём по частям:

  1. class — ключевое слово, которое говорит Python: «сейчас будет описание класса».
  2. Cat — имя класса. По соглашению (PEP 8) имена классов пишутся в стиле CamelCase: каждое слово с большой буквы, без подчёркиваний — Cat, BankAccount, StudentGroup.
  3. : и отступ — всё, что написано с отступом ниже, относится к классу (как у if и def).
  4. pass — «ничего не делать». Тело класса не может быть пустым, поэтому пока наполняем его заглушкой.

Создание объектов

Чтобы создать объект, класс «вызывают» как функцию — со скобками:

murka = Cat()
barsik = Cat()

print(type(murka))        # <class '__main__.Cat'>
print(murka is barsik)    # False — это два разных объекта
print(isinstance(murka, Cat))  # True — murka является кошкой

Обратите внимание: Cat — это сам класс, а Cat() — создание нового объекта. Каждый вызов Cat() создаёт новую, независимую кошку в памяти.

Функция isinstance(объект, Класс) отвечает на вопрос «принадлежит ли объект этому классу». Она пригодится позже, когда появятся наследники.

Проверь себя

Сколько объектов создаст код a = Cat(); b = a; c = Cat()?

Показать ответ

Два — b лишь второе имя для того же объекта, что и a.

3Конструктор __init__, self и атрибуты

Конструктор __init__ — это специальный метод, который Python вызывает автоматически сразу после создания объекта. Его задача — заполнить новый объект начальными данными. Имя пишется с двумя подчёркиваниями с каждой стороны: __init__ (от англ. initialize — «инициализировать»).

class Cat:
    def __init__(self, name, age):
        self.name = name
        self.age = age

murka = Cat("Мурка", 3)
barsik = Cat("Барсик", 5)

print(murka.name, murka.age)    # Мурка 3
print(barsik.name, barsik.age)  # Барсик 5

Что происходит при вызове Cat("Мурка", 3)

  1. Python создаёт новый пустой объект класса Cat.
  2. Python вызывает __init__ и сам подставляет этот новый объект первым аргументом — в self. В name попадает "Мурка", в age — 3.
  3. Строки self.name = name и self.age = age создают у объекта два атрибута.
  4. Готовый объект возвращается и записывается в переменную murka.

__init__ ничего не возвращает (return в нём не пишут). Он только настраивает уже созданный объект.

Что такое self

self — это ссылка на тот самый объект, с которым сейчас работает метод. Когда метод вызван для murka, self — это murka; когда для barsik — это barsik. Именно так один и тот же код класса работает с разными объектами.

🙋

Когда человек говорит «моё имя», слово «моё» у каждого означает своё. self.name — это «моё имя» с точки зрения объекта.

Правила про self, которые нужно запомнить:

  • self — всегда первый параметр обычного метода;
  • при вызове метода self не передают — Python подставляет его сам: пишем Cat("Мурка", 3), а не Cat(murka, "Мурка", 3);
  • слово self — соглашение, а не ключевое слово, но использовать другое имя — плохой тон: так никто не пишет;
  • внутри класса к атрибутам и методам объекта обращаются только через self..

Разница между name и self.name в конструкторе: name — обычный параметр функции, он исчезнет после выхода из __init__. self.name — атрибут, он остаётся в объекте, пока живёт сам объект.

Значения по умолчанию и вычисляемые атрибуты

Конструктор — обычная функция, поэтому в нём работают значения по умолчанию, проверки и вычисления. Атрибут не обязан приходить из параметра:

class Student:
    def __init__(self, name, group="ИС-21"):
        self.name = name
        self.group = group
        self.grades = []          # у каждого студента свой пустой список

anna = Student("Анна")
boris = Student("Борис", "ИС-22")

anna.grades.append(5)
print(anna.group, anna.grades)    # ИС-21 [5]
print(boris.group, boris.grades)  # ИС-22 []

Атрибуты экземпляра и атрибуты класса

Атрибуты через self. принадлежат одному объекту. Но иногда нужно значение, общее для всех объектов класса. Такой атрибут пишут прямо в теле класса, без self:

class Cat:
    species = "Кошка домашняя"   # атрибут класса — общий
    count = 0                     # счётчик созданных кошек

    def __init__(self, name):
        self.name = name          # атрибут экземпляра — свой
        Cat.count += 1            # меняем через имя класса!

a = Cat("Мурка")
b = Cat("Барсик")
print(a.species, b.species)  # Кошка домашняя Кошка домашняя
print(Cat.count)             # 2
Атрибут экземпляраАтрибут класса
Где создаётсяВ методах, через self.x = ...В теле класса, x = ...
Кому принадлежитОдному объектуВсем объектам сразу
ПримерИмя, возраст, балансВид животного, счётчик объектов, константа
Как изменитьobj.x = ...Класс.x = ...
Ловушка

Если написать a.count = 100, счётчик класса не изменится. Python создаст у объекта a новый личный атрибут count, который заслонит общий. Поэтому атрибут класса меняют через имя класса: Cat.count.

4Методы и специальные методы __str__ и __repr__

Метод — это функция, объявленная внутри класса. Он описывает, что объект умеет делать, и через self имеет доступ к данным объекта. Если атрибуты — это «что объект знает», то методы — «что объект умеет».

class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)

    def scale(self, factor):
        self.width *= factor
        self.height *= factor

    def is_square(self):
        return self.width == self.height

r = Rectangle(3, 4)
print(r.area())        # 12
print(r.perimeter())   # 14
r.scale(2)
print(r.width, r.height)  # 6 8
print(r.is_square())   # False

Методы бывают двух видов по смыслу:

  • возвращают результат и не меняют объект — area(), perimeter(), is_square();
  • меняют состояние объекта — scale(). Такие методы часто ничего не возвращают (то есть возвращают None).

Не забывайте круглые скобки при вызове: r.area() вызывает метод и даёт число, а r.area — это сам метод как объект. print(r.area) напечатает что-то вроде <bound method Rectangle.area of ...>.

Метод может вызывать другой метод

Внутри класса методы вызывают друг друга тоже через self:

    def describe(self):
        return f"Прямоугольник {self.width}x{self.height}, площадь {self.area()}"

Магические (dunder) методы

Методы, имена которых начинаются и заканчиваются двумя подчёркиваниями, называют магическими или dunder-методами (от double underscore). Их не вызывают напрямую: Python сам вызывает их в нужный момент. __init__ — первый такой метод, с которым вы познакомились.

Сразу запустите такой код — вывод вас разочарует:

r = Rectangle(3, 4)
print(r)   # <__main__.Rectangle object at 0x0000021F3A8B5D50>

Python не знает, как красиво показать наш объект, и печатает имя класса и адрес в памяти. Исправим это:

class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def __str__(self):
        return f"Прямоугольник {self.width}x{self.height}"

    def __repr__(self):
        return f"Rectangle({self.width}, {self.height})"

r = Rectangle(3, 4)
print(r)          # Прямоугольник 3x4      ← __str__
print(str(r))     # Прямоугольник 3x4      ← __str__
print(repr(r))    # Rectangle(3, 4)            ← __repr__
print([r, r])     # [Rectangle(3, 4), Rectangle(3, 4)]  ← в списке — __repr__
МетодДля когоКогда вызывается
__str__Для пользователя: понятный текстprint(obj), str(obj), f-строки
__repr__Для программиста: точное описание, в идеале — как воссоздать объектrepr(obj), вывод в консоли, внутри списков и словарей

Оба метода обязаны возвращать строку (return), а не печатать её. Если есть только __repr__, Python использует его и для print.

Другие полезные магические методы (для знакомства):

5Инкапсуляция

Инкапсуляция — это принцип, по которому объект скрывает своё внутреннее устройство и даёт работать со своими данными только через свои методы. Так объект сам следит, чтобы его данные оставались корректными.

🏧

У банкомата есть экран и кнопки — это его «публичный интерфейс». Деньги лежат внутри в сейфе, и достать их руками нельзя. Вы просите снять 1000, банкомат сам проверяет баланс и решает, выдавать ли деньги.

Уровни доступа в Python

В Python нет ключевых слов private и public, как в C# или Java. Вместо них используют соглашения об именах:

ЗаписьНазваниеЧто означает
self.nameПубличныйМожно свободно читать и менять снаружи
self._nameЗащищённый«Внутреннее, не трогайте». Доступ технически есть, но это просьба к другим программистам
self.__nameПриватныйPython переименовывает атрибут в _Класс__name, и по имени obj.__name снаружи его уже не найти

Переименование с двумя подчёркиваниями называется name mangling. Это не настоящая защита, а защита от случайного доступа: в Python принято доверять программисту («мы все взрослые люди»).

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance      # приватный атрибут

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        self.__balance += amount

    def withdraw(self, amount):
        if amount > self.__balance:
            raise ValueError("Недостаточно средств")
        self.__balance -= amount

    def get_balance(self):
        return self.__balance

acc = BankAccount("Анна", 1000)
acc.deposit(500)
print(acc.get_balance())   # 1500
print(acc.__balance)       # AttributeError: 'BankAccount' object has no attribute '__balance'

Теперь баланс меняется только через deposit и withdraw, а те проверяют данные. raise ValueError(...) — это способ сообщить об ошибке: программа остановится с понятным сообщением, если ошибку не перехватить через try/except.

Свойства: декоратор @property

Писать get_balance() и set_balance() неудобно. Python предлагает более изящный способ — свойства. Снаружи они выглядят как обычный атрибут, но внутри при чтении и записи вызываются методы.

class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age          # здесь уже сработает сеттер!

    @property
    def age(self):              # геттер — чтение
        return self._age

    @age.setter
    def age(self, value):       # сеттер — запись с проверкой
        if not 14 <= value <= 100:
            raise ValueError("Возраст должен быть от 14 до 100")
        self._age = value

s = Student("Анна", 19)
print(s.age)    # 19     ← без скобок, как атрибут
s.age = 20      # вызывается сеттер, проверка проходит
s.age = -5      # ValueError: Возраст должен быть от 14 до 100

Как это устроено:

  1. @property превращает метод age в свойство. Теперь s.age вызывает этот метод без скобок.
  2. @age.setter описывает, что делать при присваивании s.age = .... Имя метода должно совпадать с именем свойства.
  3. Реальное значение хранится в self._age — с подчёркиванием. Если написать в сеттере self.age = value, сеттер будет вызывать сам себя бесконечно (RecursionError).
  4. В __init__ мы пишем self.age = age, а не self._age — тогда проверка сработает и при создании объекта.

Свойство без сеттера доступно только для чтения. Так удобно делать вычисляемые значения:

class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return 3.14159 * self.radius ** 2

c = Circle(2)
print(c.area)   # 12.56636
c.area = 100    # AttributeError: property 'area' of 'Circle' object has no setter

6Наследование

Наследование — это создание нового класса на основе уже существующего. Новый класс (дочерний, наследник) получает все атрибуты и методы старого (родительского, базового) и может добавить свои или изменить унаследованные. Так общий код пишется один раз.

Наследование описывает отношение «является» (is-a): собака является животным, студент является человеком. Если фраза «X является Y» звучит странно («машина является двигателем»), наследование тут не подходит: у машины двигатель просто есть (это атрибут).

Синтаксис

Родительский класс указывают в скобках после имени нового класса: class Dog(Animal):.

class Animal:
    def __init__(self, name):
        self.name = name

    def info(self):
        return f"Я {self.name}"

    def speak(self):
        return "..."


class Dog(Animal):
    def speak(self):              # переопределяем
        return "Гав!"

    def fetch(self):              # добавляем новое
        return f"{self.name} принёс мячик"


class Cat(Animal):
    def speak(self):
        return "Мяу!"

    def purr(self):
        return "Мрррр..."


rex = Dog("Рекс")
print(rex.info())    # Я Рекс        ← метод родителя
print(rex.speak())   # Гав!           ← своя версия
print(rex.fetch())   # Рекс принёс мячик

print(isinstance(rex, Dog))     # True
print(isinstance(rex, Animal))  # True — собака является животным
print(issubclass(Cat, Animal))  # True

У Dog нет своего __init__ и info, но они работают — взяты у Animal. Когда вы вызываете метод, Python ищет его сначала в классе объекта, потом в родителе, потом в родителе родителя — и берёт первый найденный. Поэтому rex.speak() даёт «Гав!», а не «...».

Переопределение метода (override) — это когда наследник объявляет метод с тем же именем, что и у родителя. Версия наследника заменяет родительскую для его объектов.

Функция super()

Часто наследнику нужны дополнительные атрибуты, и ему нужен свой __init__. Но тогда родительский __init__ автоматически больше не вызывается. Чтобы не копировать его код, его вызывают через super() — функцию, которая даёт доступ к методам родителя.

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"{self.name}, {self.age} лет"


class Student(Person):
    def __init__(self, name, age, group):
        super().__init__(name, age)   # родитель заполнит name и age
        self.group = group            # а это — новое поле

    def __str__(self):
        base = super().__str__()      # берём текст родителя...
        return f"{base}, группа {self.group}"  # ...и дополняем


s = Student("Анна", 19, "ИС-21")
print(s)   # Анна, 19 лет, группа ИС-21

Если забыть строку super().__init__(name, age), у студента не появятся атрибуты name и age, и print(s) упадёт с AttributeError.

Иерархии и класс object

Наследовать можно цепочкой: Person → Student → Graduate. Все классы в Python неявно наследуются от встроенного класса object — именно оттуда берётся стандартный __str__, который печатает <... object at 0x...>. Запись class Cat: равносильна class Cat(object):.

Python также допускает множественное наследование (class C(A, B):), но новичкам его лучше пока не использовать.

Проверь себя

Что напечатает Cat("Мурка").info() и почему это работает, хотя в Cat нет метода info? Зачем в Student.__init__ нужен super()?

7Полиморфизм и абстракция

Полиморфизм

Полиморфизм (с греческого «много форм») — это способность одного и того же кода работать с объектами разных классов. Мы вызываем метод с одним именем, а каждый объект выполняет его по-своему.

🔌

Кнопка «Включить» есть у телевизора, чайника и компьютера. Вы нажимаете одну и ту же кнопку, а каждый прибор делает своё: показывает картинку, греет воду, загружает систему.

animals = [Dog("Рекс"), Cat("Мурка"), Dog("Шарик")]

for animal in animals:
    print(f"{animal.name}: {animal.speak()}")

# Рекс: Гав!
# Мурка: Мяу!
# Шарик: Гав!

Цикл не знает и не проверяет, какое именно животное перед ним. Он просто вызывает speak(). Без полиморфизма пришлось бы писать так:

# Плохо: при каждом новом животном нужно править этот if
if type(animal) == Dog:
    print("Гав!")
elif type(animal) == Cat:
    print("Мяу!")

С полиморфизмом добавить корову — значит написать класс Cow(Animal) с методом speak(). Цикл менять не нужно.

Утиная типизация. В Python полиморфизм работает даже без общего родителя. Важно лишь, чтобы у объекта был нужный метод: «если нечто ходит как утка и крякает как утка, то это утка».

class Robot:
    name = "R2-D2"
    def speak(self):
        return "Бип-буп!"

for thing in [Dog("Рекс"), Robot()]:
    print(thing.speak())   # Гав!  Бип-буп!

Встроенный пример полиморфизма — функция len(): она работает со строками, списками и словарями, потому что у каждого из этих классов есть свой __len__. Оператор + тоже полиморфен: 2 + 3 складывает числа, "a" + "b" склеивает строки.

Абстракция

Абстракция — это выделение главного и отбрасывание неважного. Класс описывает только те свойства и действия, которые нужны программе. Для деканата студент — это ФИО, группа и оценки; цвет глаз и любимая еда в класс Student не попадут.

Вторая сторона абстракции — работать с объектом, не зная его устройства. Вы вызываете list.sort() и не думаете, какой алгоритм сортировки внутри.

Иногда класс создаётся только как общий «шаблон для наследников», и создавать его объекты не имеет смысла. Какая площадь у «просто фигуры»? Никакая. Такие классы называют абстрактными. В Python для них есть модуль abc (Abstract Base Classes):

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

    def describe(self):                       # обычный метод тоже можно
        return f"{type(self).__name__}, площадь {self.area():.2f}"


class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2


class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2


shapes = [Square(3), Circle(1)]
for s in shapes:
    print(s.describe())
# Square, площадь 9.00
# Circle, площадь 3.14

Shape()   # TypeError: Can't instantiate abstract class Shape ...

Что здесь важно:

  • класс наследуется от ABC, а метод помечен @abstractmethod;
  • создать объект Shape() нельзя — Python выдаст ошибку;
  • наследник обязан реализовать все абстрактные методы, иначе его объект тоже не создать. Это защищает от забытого метода;
  • метод describe написан один раз и работает для любой фигуры — абстракция, наследование и полиморфизм работают вместе.

Итог: четыре принципа ООП

Абстракция

Описываем только важное, скрываем детали

Классы, ABC, @abstractmethod

Инкапсуляция

Данные спрятаны, доступ — через методы с проверками

_x, __x, @property

Наследование

Новый класс берёт всё у старого и дополняет

class B(A), super()

Полиморфизм

Один вызов — разное поведение у разных объектов

Переопределение методов, утиная типизация
Проверь себя

Добавьте в пример класс Triangle(Shape) без метода area. Что произойдёт при попытке создать Triangle() и почему это полезно?

Ошибка без сообщения: изменяемый атрибут класса

Самая коварная ошибка — программа не падает, но работает неверно:

class Student:
    grades = []                  # ОШИБКА: один список на всех!

    def __init__(self, name):
        self.name = name

a = Student("Анна")
b = Student("Борис")
a.grades.append(5)
print(b.grades)   # [5] — Борис «получил» оценку Анны

Список, объявленный в теле класса, один на все объекты. Списки, словари и множества, которые должны быть у каждого свои, создавайте в __init__: self.grades = [].

Та же ловушка срабатывает со значением по умолчанию: def __init__(self, grades=[]) создаёт один список на все вызовы. Правильно так:

def __init__(self, name, grades=None):
    self.name = name
    self.grades = grades if grades is not None else []

Путаница класса и объекта

Student.name          # ОШИБКА: у класса нет имени, имя есть у конкретного студента
s = Student           # ОШИБКА: забыли скобки, s — это сам класс
s = Student("Анна")   # правильно: s — объект

Отступы

Методы должны быть с отступом внутри class. Если def начать с начала строки, это уже обычная функция, а не метод, и вызов obj.method() даст AttributeError. Используйте 4 пробела на уровень и не смешивайте пробелы с табуляцией.
